# Лабораторная 4. Утилита pick-lines

Напишите программу, которая выбирает строки текста по номерам. Например, пусть в файле `shopping.txt` четыре строки:

```text
milk
eggs
bread
tea
```

После выполнения лабораторной из каталога `Lab4` можно будет запустить:

```console
$ stack run pick-lines -- --lines 1,3-4 --number shopping.txt
1: milk
3: bread
4: tea
$ stack run pick-lines -- --lines 1,3-4 --invert shopping.txt
eggs
```

## 1. Разберите выбор строк

В [LineRange.hs](src/LineRange.hs) реализуйте `mkRange lo hi`. Если `1 ≤ lo ≤ hi`, верните `Just (LineRange lo hi)`, иначе — `Nothing`.

В [Selection.hs](src/Selection.hs) реализуйте `parseSelection` с помощью [Megaparsec](https://hackage.haskell.org/package/megaparsec/docs/Text-Megaparsec.html). Используйте `mkRange` для проверки границ каждого элемента. Для одиночного номера обе границы совпадают. Значение аргумента `--lines` задаётся такой грамматикой:

```text
выбор   ::= элемент ("," элемент)*
элемент ::= номер ("-" номер)?
```

Номер состоит из десятичных цифр и должен быть положительным. Границы диапазона включены, левая граница не превосходит правую. Например, `3-3` выбирает одну строку. Пробелы в записи не допускаются. Разберите аргумент целиком: `2-4x` должно давать ошибку, даже если начало удалось разобрать. См. [лекцию 15 о комбинаторах парсеров](../lecture15_parser_combinators.pdf).

## 2. Выберите строки

В том же модуле реализуйте чистую функцию `selectLines`. Нумерация начинается с 1, пустая строка тоже получает номер. Сохраняйте порядок исходного текста, даже если диапазоны перечислены в другом порядке. При пересечении диапазонов выводите строку один раз. Номера за концом текста ничего не выбирают. С флагом `--invert` выбирайте все строки, номера которых не входят ни в один из диапазонов.

## 3. Опишите командную строку

В [CLI.hs](src/CLI.hs) реализуйте парсер `options` с помощью [optparse-applicative](https://hackage.haskell.org/package/optparse-applicative/docs/Options-Applicative.html):

```text
pick-lines --lines SELECTION [--number] [--invert] [FILE]
```

Аргумент `--lines` обязателен. Используйте `parseSelection` для разбора его значения. При неверном выборе программа должна сообщить об ошибке до чтения файла. Флаги независимы и по умолчанию выключены. Для `--help` добавьте описание каждого аргумента.

## 4. Соедините разбор и ввод-вывод

Точка входа в [Main.hs](app/Main.hs) уже вызывает `run` после разбора аргументов. Реализуйте `run`: прочитайте файл `FILE`, а если имя не задано — стандартный ввод. Примените `selectLines` и выведите каждую выбранную строку на стандартный вывод с переводом строки. При `--number` добавляйте перед текстом исходный номер и разделитель `": "`. Если ничего не выбрано, вывод пуст.

## Необязательно: диапазоны с одной границей

Расширьте `--lines`: запись `-n` выбирает строки с первой по `n` включительно, а `n-` — с `n`-й до конца ввода. Например, для текста из шести строк `--lines=-2,5-` выбирает строки 1, 2, 5 и 6. Одиночный `-` считается ошибкой.

Выберите представление диапазонов самостоятельно. Если измените `LineRange` и `mkRange` и будете выполнять задание по Liquid Haskell о границах диапазона, обновите их уточнения для нового представления.

## Проверка

Запускайте `stack test` из каталога `Lab4`. В [Spec.hs](test/Spec.hs) часть примеров уже записана: снимайте `pending` по мере реализации. Для остальных напишите проверки. Аргументы командной строки можно проверять через `execParserPure`, без запуска отдельного процесса.

В группе «Ввод-вывод» дан готовый пример: он запускает саму утилиту, передаёт текст на стандартный ввод и проверяет код завершения, сообщения об ошибках и стандартный вывод. После реализации утилиты снимите `pending` и напишите по этому образцу проверку чтения из файла.

Добавьте свойство Hedgehog: для небольших положительных `a ≤ b` запись диапазона `a-b` и перечисление всех номеров от `a` до `b` выбирают одни и те же строки. Разберите обе записи и сравните результаты на сгенерированном тексте. В Hspec результат `check` можно проверить через `shouldReturn True`.

## Необязательно: два задания на Liquid Haskell

1. **Усильте контракт `mkRange`.** В [LineRange.hs](src/LineRange.hs) уточнение типа конструктора уже гарантирует корректность каждого созданного диапазона. Добавьте к функции из задания 1 уточнённую сигнатуру, которая полностью определяет результат для любой пары границ. При допустимых границах функция должна вернуть именно их в `Just`, при недопустимых — `Nothing`. Проверьте свою реализацию. Затем временно замените её на функцию, которая всегда возвращает `Nothing`, убедитесь, что Liquid Haskell отклоняет её, и восстановите исходную реализацию.
2. **Докажите свойство выбора с `--invert`.** Функция [`pick`](src/Pick.hs) оставляет элементы, удовлетворяющие предикату. Её можно импортировать в `Selection` для отбора пронумерованных строк в `selectLines`. В [PickExercise.hs](proofs/PickExercise.hs) эта же функция уже импортирована. Докажите по индукции по списку, что сумма длин результатов для предиката `p` и его отрицания равна длине входа. Сигнатура леммы `partitionLength` уже дана. Обнаружило бы это свойство ошибку, при которой строки выводятся в обратном порядке?

Задания независимы. Для проверки нужен Z3 в `PATH`. Из каталога `Lab4` соберите плагин и библиотеку комбинаторов, затем запустите команду для своего задания:

$ stack exec -- ghc -fplugin=LiquidHaskell -fforce-recomp -isrc -outputdir .stack-work/proofs --make proofs/PickExercise.hs
